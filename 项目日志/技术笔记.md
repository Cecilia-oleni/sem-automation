1. 全局环境与虚拟环境
是两个独立环境，可以并行存在。会出问题的情况一般只有一种：你运行代码时用错了解释器。
modules 和 main.py 代码本身不针对全局环境，也不针对虚拟环境
至于去哪里找代码里的库，取决于你运行代码时使用的 Python 解释器。

2. 创建虚拟环境标准sop

新建一个项目文件夹，先用 VS Code 打开这个项目文件夹，不是只打开某个 .py 文件。

然后在 VS Code 终端里执行：
python -m venv .venv

创建虚拟环境后激活：
.\.venv\Scripts\Activate.ps1

如果成功，终端前面应该出现：
(.venv) PS ...

然后再安装包，尽量使用：
python -m pip install 包名

不要直接用pip install 包名
因为 python -m pip 会跟随当前 Python 环境，更不容易装错地方。

每个项目都建议放一个 .vscode/settings.json
{
  "python.defaultInterpreterPath": "${workspaceFolder}\\.venv\\Scripts\\python.exe",
  "python.terminal.activateEnvironment": true
}

这样 VS Code 打开这个项目时，会优先使用当前项目下的：
.venv\Scripts\python.exe


3. 怎么确认自己有没有用错环境？

终端输入：
python -c "import sys; print(sys.executable)"

如果输出路径里有：
\.venv\Scripts\python.exe
就说明当前用的是虚拟环境。

3. Openrouter的替代方案：
方案 1：继续用 OpenRouter，但先用免费模型或 BYOK
OpenRouter 的优势是“一个接口接多个模型”，它的文档说明其 API 和 OpenAI Chat API 很相似，也支持用 OpenAI SDK 调用；另外它支持 OpenRouter credits 和 BYOK，也就是把你自己的模型供应商 API Key 接入 OpenRouter。
如果暂时付款困难，可以先测试 OpenRouter 的免费模型路由，但免费模型通常不适合长期稳定生产，只适合你现在跑通流程。OpenRouter 也有 free-variant models 页面，但具体可用模型和限制会变化。

方案 2：直接接 DeepSeek API
DeepSeek 官方文档说明它的 API 格式兼容 OpenAI/Anthropic，所以你的 llm_client.py 可以继续用“类似 OpenAI SDK 的写法”，只需要换 api_key、base_url 和 model。
这对你很合适，因为测试阶段成本较低，而且中文分析、资料摘要、关键词初稿这类任务，DeepSeek 基本够用。

方案 3：接国内中转/模型平台，比如 SiliconFlow
SiliconFlow 文档说明可以用 OpenAI 相关接口调用，并支持大部分 OpenAI 相关参数。
这类平台的好处是可能更适合国内网络和支付环境，也能调用 DeepSeek、Qwen 等模型。具体支付方式要以你注册后台当前显示为准。

方案 4：接阿里云百炼 / Model Studio
阿里云 Model Studio 文档说明它支持 OpenAI-compatible 接口，迁移时主要改 API key、base URL 和 model name。
如果后续想用 Qwen 系列模型做中文资料分析，国内云平台可能比海外平台更容易处理账号和付款问题。

方案 5：本地模型，完全不走付费 API
比如 Ollama。Ollama 官方文档说明它有本地 API，并有 Python / JavaScript 官方库；它需要你本地安装并运行模型。

这个方案不用海外信用卡，也不用上传客户资料到外部 API。但缺点是：对电脑性能有要求，分析长资料时速度慢，效果也可能不如云端大模型。

1. 了解git在version control上的作用，git+github管理版本并能共享给其它人
2. Linux与windows部分符号格式转换：终端执行git config --global core.autocrlf true
3. 中文的文件名（如技术笔记.md、开发日志.md）在git中可能会被上传为乱码，这不代表文件名本身错误。
因为Git 在 Windows 默认：
用 GBK/CP936 显示中文
VS Code / terminal 用 UTF-8
如何确认：git status --porcelain
解决方法：
1）解决乱码：git config --global core.quotepath false  
让 Git 正常显示中文文件名，不再显示 \351\241 这种乱码
2）如果文件名真变乱码，需要重命名：git mv 旧文件名 新文件名  
再确认：git status --porcelain
或者：git diff --name-only  看真实文件名

4. 如何使用git和github进行版本管理和持续迭代：
  1）修改代码
  2）终端输入：git status，查看改动
  3）加入暂存区，名称类似：git add modules/ad_copy_generator.py
  4）写commit，例如：git commit -m "feat: add negative keyword analyzer optimization" （说明这次改动了什么）
  5）git push

  建议格式：
  1）功能新增：feat: add ad copy generator
  2）优化：refactor: optimize keyword grouping logic
  3）修改bug：fix: correct wordstat parsing error
  4）重构：refactor: restructure llm client layer

5. 只是覆盖前一个版本，不做版本管理：
git add .
git commit -m "update"
git push
github上永远是最新代码（自动覆盖旧版本），且可以回退

进阶：按日期管理版本，示例
git commit -m "v1 2026.07.01 keyword system"
git commit -m "v2 2026.07.02 negative keyword update"
默认看到最新版本，历史里有 v1/v2/v3，可以随时回退

打tag：
git tag v1_20260701
git tag v2_20260702
git push --tags
