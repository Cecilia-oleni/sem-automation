# 将项目目录更名为 sem自动化

目标：`D:\sem自动化`。当前项目仍在 `D:\sem自动化 - 副本`。

此前直接更名失败，备用逐项迁移也被 Windows 拒绝访问 `.git`。错误本身不能证明是权限还是占用；在仍打开旧项目的 VS Code 集成终端中运行，会保留父进程对旧目录的占用。移动内容已回退，项目和 Git 历史仍在原目录。脚本现已取消逐项迁移，整体更名失败即停止，并阻止从 VS Code 集成终端运行。不要删除 `.git` 或修改保护权限。

## 已定位的占用与本次收尾方式

句柄检查确认：Codex 的电脑操作后台进程占用了项目根目录，已释放；另外主窗口进程名为 `ChatGPT.exe`（本次 PID 8332，实际路径在 `OpenAI.Codex_26.915.4065.0` 安装包内），持有根目录和 `.git` 的14个句柄。仅凭“访问被拒绝”不能判断为权限问题。

本次可在独立 PowerShell 执行以下收尾脚本。它先核对 PID、程序完整路径和精确启动时间，提示保存工作；输入 YES 后才关闭这个已确认的 Codex 主窗口，然后立即执行迁移和验收。不会关闭其他同名应用。若 PID 已被其他进程复用会停止，需重新诊断。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'D:\sem自动化 - 副本\experiments\archive\migration\finish_rename.ps1'
```

看到成功信息之前不要重新打开 Codex 或旧项目。日志位于 Windows 临时目录的 `sem-finish-rename.log`。

## 常规更名方式

先复制下方命令并保存文件，完全退出使用旧项目的 VS Code 和 Codex，关闭旧终端。按 Win+R，输入 powershell 并回车，打开独立 PowerShell，再复制执行：

```powershell
Set-Location -LiteralPath 'D:\'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'D:\sem自动化 - 副本\experiments\archive\migration\rename_sem.ps1'
```

脚本会检查源和目标的绝对路径；目标存在文件时停止，只有此前迁移尝试留下的空目标目录可清理。然后只执行整体更名；失败即停止，不再尝试拆分移动 `.git` 或其他子目录。不会覆盖另一份项目或删除客户文件。

迁移后自动更新正式代码与文档路径，重建虚拟环境的启动器，修正 VS Code 任务，并运行 Python 测试、pip 检查、统一入口帮助和宇通八月输入检查。既有包版本保留，不联网重装。旧历史数据与带指纹报告清单不批量改写。

看到 `RENAMED_AND_VERIFIED: D:\sem自动化` 后，在 VS Code 和 Codex 中重新打开 `D:\sem自动化`。更名后验证：

```powershell
Set-Location -LiteralPath 'D:\sem自动化'
& '.\.venv\Scripts\python.exe' -X utf8 '.\sem.py' materials run --project '通亚' --dry-run
```

若目录已移动但环境修复失败，不要再运行前面的搬迁命令。保留新目录，查看具体错误；环境修复可单独运行：

```powershell
& 'D:\sem自动化\.venv\Scripts\python.exe' -X utf8 'D:\sem自动化\experiments\archive\migration\fix_renamed_environment.py'
```

迁移前记录、VS Code 原配置、依赖版本和测试日志位于 `outputs/_migration/2026-09-22/`。本脚本没有 Git 提交或推送操作。
