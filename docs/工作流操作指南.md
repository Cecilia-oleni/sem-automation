# 工作流操作指南

按 2026-09-22 的代码整理。日常只需记住：**放好资料 → 运行命令 → 按提示补人工文件 → 用同一命令继续 → 取结果**。

## 1. 整体是什么结构

`sem.py` 是总入口，`cli` 识别你输入的命令，各个 `pipeline.py` 安排步骤。可以把 pipeline 理解为“流程负责人”，其他模块负责具体工作。

```text
sem.py（总入口）
├─ materials run → 资料 → 关键词与人工审核 → 否词、广告语、附加信息
└─ reports       → 选通用 / 安琪 / 宇通 → 读取数据 → 计算核对 → Excel
```

两条业务互相独立，三类月报也分别运行。目录变多主要是功能分开存放，不代表你需要启动更多程序。

| 模块（以下路径都在 sem_automation 下） | 通俗解释 | 日常需要单独运行吗 |
|---|---|---|
| `materials/context/` | 读客户资料、抓网站、合并文字、写项目分析 | 通常随物料流程；部分可单跑 |
| `materials/keywords/` | 起草关键词、导出查询词、清洗人工搜索量 | 可单跑；不自动查询 Wordstat 或最终分组 |
| `materials/negatives/`、`ads/`、`extensions/` | 分别生成否词、广告语、附加链接和短卖点 | 可单跑，须已有上游文件 |
| `reporting/standard/` | 通用报告：Direct 广告数据 + Metrika 网站数据 | 用 `reports standard` |
| `reporting/angel_yeast/` | 安琪专用计算，生成基础、关键词、品类三份表 | 用 `reports angel-yeast` |
| `reporting/yutong/` | 宇通本地数据月报、历史表候选副本与同步 | 用 `reports yutong`；同步另跑 |
| `reporting/renderers/`、`common/` | 把数据排成 Excel，以及共用日期处理 | 不需要；`.mjs` 是流程自动调用的制表脚本 |
| `ai/` | 加载提示词、联系模型、保存 AI 结果 | 不需要 |
| `readers/` | 提取 Word、Excel、PDF、网页里的文字 | 不需要；图片 OCR 尚未启用 |
| `integrations/yandex/` | 与 Direct / Metrika 接口交换数据 | 不需要，由报告调用 |
| `core/`、`cli/` | 找文件、记运行记录、分发命令 | 不需要 |

根目录最常用的是 `uploads/`（原资料）、`outputs/`（结果）、`config/`（客户和月份设置）。`prompts/` 是 AI 任务说明，`templates/` 是 Excel 模板；改生成要求或版式时才需关注。

`tests/` 是开发检查；`experiments/wordstat/` 是未接入正式流程的查询实验；`experiments/archive/` 是旧脚本和日志；`outputs/_archive/` 是旧报告数据；`outputs/_migration/` 是重构快照。根目录 `wordstat-api-lab/` 当前仅保留词表，不是运行入口。`.venv/`、`node_modules/` 是运行依赖，`__pycache__/` 是缓存。

## 2. 物料怎么跑、每步怎么交接

在 VS Code 的 PowerShell 终端运行。以下用“通亚”举例，换成你的项目名：

```powershell
Set-Location -LiteralPath 'D:\sem自动化 - 副本'
# 预览流程，不联网、不写文件
& '.\.venv\Scripts\python.exe' -X utf8 '.\sem.py' materials run --project '通亚' --dry-run
# 正式运行；AI 步骤会调用模型，有网站时会抓网页
& '.\.venv\Scripts\python.exe' -X utf8 '.\sem.py' materials run --project '通亚'
```

先建好 `uploads/materials/通亚/`，放入客户资料，建议用 `.docx`、`.xlsx`、可提取文字的 PDF。图片和扫描件目前不能自动识别文字。输出统一在 `outputs/materials/通亚/`。

**物料模块主要靠文件交接：上一步保存文件，下一步按固定文件名读取。** 不需要你在模块间复制粘贴；只有下面标“人工”的三步需要你准备文件。表里的文件名均相对于该项目的输出目录。

| 顺序 / 模块 | 读取什么 | 交给下一步什么 |
|---|---|---|
| 1. `context/collect.py` 读资料 | `uploads/materials/项目名/` 的文件 | `raw_text_local.txt` 本地文字；识别到官网时另存 `website_urls.txt` |
| 2. `context/crawl.py` 读网站 | `website_urls.txt` | `website_pages.json` 给程序用，`website_content.md` 给人看 |
| 3. `context/source_context.py` 合并 | 本地文字 + 可用网页内容 | `raw_text.txt`，作为统一资料底稿 |
| 4. `context/brief.py` 项目分析 | `raw_text.txt` | `project_brief.md` |
| 5. `keywords/draft.py` 关键词初稿 | 底稿 + 项目分析 | `keyword_v1.md` |
| 6. **人工审核** | `keyword_v1.md` | 修改后另存 `keyword_v1_reviewed.md` |
| 7. `keywords/wordstat.py` 导出查询词 | 审核版关键词 | `wordstat_query_list.txt`，交给你查询搜索量 |
| 8. **人工查询 Wordstat** | 查询词清单 | `wordstat_results_manual.txt`，每行“关键词 + 搜索量”，推荐用 Tab 分隔 |
| 9. `keywords/clean.py` 清洗 | 人工查询结果 | `wordstat_results_cleaned.tsv` |
| 10. **人工筛选、分组** | 清洗后的词和搜索量 | `keyword_v2.xlsx`（也接受 `keywords_v2.xlsx`） |
| 11. `negatives/generator.py` 否词 | 底稿 + 项目分析 + 分组版关键词 | `negative_keywords.md` |
| 12. `ads/generator.py` 广告语 | 项目分析 + 分组版关键词 + 否词 | `ad_copy_results.xlsx` / `.tsv`；`ad_copy_raw.md` 留存原文 |
| 独立分支：`extensions/generator.py` | 项目分析 + 网站页面（如有） | `sitelink_callouts.xlsx` / `.json`，以及 `sitelink_callouts_raw.md` 原文 |

分组表最简单的格式是第一行写 `Campaign`、`AdGroup`、`Keyword` 三列表头，后面每行一个关键词，并填齐广告系列和广告组。清洗后的 TSV 若有“无法解析”记录，先人工处理再分组。

没有网站会跳过抓取，附加信息只生成 Callout（短卖点），不生成 Sitelink（附加链接）。若配置了网站但抓取失败，有本地资料时主流程可继续，附加信息分支会等待可用网页。补官网可在正式命令后加 `--website 'https://你的客户域名'`；此参数会替换该项目现有网址清单。

**停在人工节点不等于报错。** 按上表把文件保存到输出目录，再运行同一条正式命令。遇到已有结果：`1` 保留、`2` 覆盖重做、`3` 停止，直接回车默认保留。等待关键词审核时也可按提示先生成附加信息，它不依赖关键词分组和广告语。

**改了上游资料，不会自动刷新所有下游结果。** 例如改了分组表，要重新生成否词和广告语，就在续跑时对这两步选择 `2`。人工审核文件也需要自己复核；程序主要检查文件是否存在，不能替你判断内容是否审核完毕。

## 3. 能不能只跑某个模块

可以。整套流程最省心；只重做一步时，可用下面的单模块入口。**单跑不会补齐上游，也没有总流程的覆盖确认，可能直接覆盖该模块结果。** 先保留你改过的成品；单跑后若还要更新下游，需要再运行下游。

例如只重新生成广告语（需已有项目分析、分组表和否词）：

```powershell
& '.\.venv\Scripts\python.exe' -X utf8 -m sem_automation.materials.ads.generator --project '通亚'
```

其他入口使用同一个命令格式，把 `-m` 后面的部分替换为下表内容；不要把所有行依次运行。所需文件见上面的交接表。

| 只做什么 | `-m` 后填写 |
|---|---|
| 读本地资料 | `sem_automation.materials.context.collect`（启动后输入项目名；只提取，不合并） |
| 读取网站 | `sem_automation.materials.context.crawl --project '通亚'` |
| 项目分析 | `sem_automation.materials.context.brief`（启动后输入项目名） |
| 关键词初稿 | `sem_automation.materials.keywords.draft`（启动后输入项目名） |
| 导出查询词 | `sem_automation.materials.keywords.wordstat --project '通亚'` |
| 清洗搜索量 | `sem_automation.materials.keywords.clean --project '通亚'` |
| 否词 | `sem_automation.materials.negatives.generator`（输入项目名后，关键词版本直接回车） |
| 附加链接 / 短卖点 | `sem_automation.materials.extensions.generator --project '通亚'` |

资料合并没有独立命令，需要跑总流程。单独生成否词时，若没有分组表，会退回参考初稿；要按最终分组生成，请先准备分组表。AI、读取器、平台客户端这些公共模块由业务模块调用，不是日常操作入口。

## 4. 月报怎么跑、交接什么

月报总体是“配置 + 数据 → 计算和核对 → 制表 → Excel”，不读取物料关键词文件。以下是已有月份的例子；换月准备和联网命令见 [月报操作说明](月报操作说明.md)。

```powershell
# 宇通：读取本地 Excel；先只检查，再去掉 --check-only 生成
& '.\.venv\Scripts\python.exe' -X utf8 '.\sem.py' reports yutong --config '.\config\reports\yutong\2026-08.json' --month 2026-08 --check-only

# 安琪：复用已有数据；不发起新翻译
& '.\.venv\Scripts\python.exe' -X utf8 '.\sem.py' reports angel-yeast --config '.\config\angel_yeast_direct_monthly.json' --month 2026-08 --reuse-raw '.\outputs\_archive\angel_yeast\2026-08\_internal\direct_monthly_data.json' --skip-translation

# 通用：复用凌宇已有 Direct + Metrika 数据
& '.\.venv\Scripts\python.exe' -X utf8 '.\sem.py' reports standard --client '.\config\clients\lingyu.json' --month 2026-07 --source existing --data-dir '.\outputs\_archive\lingyu\2026-07'
```

| 流程 | 模块之间用什么交接 | 你要做什么 |
|---|---|---|
| 通用 | Direct / Metrika 采集或复用 → `_internal/direct_monthly_data.json` 和 `_internal/metrika/metrika_monthly_data.json` → 总流程校验并写 `_internal/report_bundle.json` → 制表模块生成 Excel | 选客户、期间和数据来源；两个 JSON 要来自同客户同期间 |
| 安琪 | `dataset.py` 采集或重算 → `_internal/direct_monthly_data.json` → 专用制表模块 → 三份 Excel | 核对客户配置；安琪 JSON 不能拿去当通用报告输入 |
| 宇通 | 月份配置指向源 Excel、模板、历史表 → `_internal/resolved_config.json` 把路径和参数交给制表模块 → 核对报告、生成历史候选表 → `_internal/manifest.json` 交给同步模块 | 准备配置引用的文件；检查成品和候选表后，才按月报说明单独执行 `sync` |

JSON 是程序保存的结构化数据或运行清单，通常不需要你编辑。各步骤会自动传路径、调用下一个模块，**不用手动启动每个制表脚本**。宇通同步同时读取清单和 `history_candidates/` 里的候选表；只生成月报不会改真实历史表。

## 5. 去哪里取结果、卡住看哪里

| 情况 | 看哪里 / 怎么办 |
|---|---|
| 取物料 | `outputs/materials/项目名/`：分组表、`negative_keywords.md`、`ad_copy_results.xlsx`、`sitelink_callouts.xlsx` |
| 取月报 | 终端打印的新运行目录下 `deliverables/`；每次生成是新目录 |
| 等待人工处理 | 按提示补文件到物料输出目录，核对文件名，再用原命令续跑 |
| 资料未读到 | 查看物料目录 `file_report.csv`、`web_report.csv`；扫描图片需先转成可读文字 |
| 物料失败 | 查看终端与 `pipeline_status.json`，它记录步骤状态；实际交接仍靠上表中的文件 |
| 报告失败 | 查看终端和本次 `_internal/status.json`（已创建运行目录时）；宇通另看 `workbook_checks.json` |
| 找不到 Python / Node 或缺依赖 | 看 [README 的环境说明](../README.md#环境与测试)；月报还需要 Node 和制表依赖 |

生成物料到这里产出的是待审核文件，当前没有自动上传到广告账户的步骤。
